# ONEBOOK — ระบบบัญชีกลุ่มบริษัท

ระบบบัญชีออนไลน์สำหรับใช้ **ภายในองค์กร** รองรับหลายบริษัทในเครือ สร้างด้วย Next.js 14 (App Router) + TypeScript +
Tailwind CSS + Supabase (PostgreSQL) ออกแบบตามแนวทางโปรแกรมบัญชีไทย (ผังบัญชีมาตรฐาน DBD, VAT 7%,
ภาษีหัก ณ ที่จ่ายตามประมวลรัษฎากร) โหมดสว่าง UI ทางการ รองรับ **ไทย / 中文 / English**

---

## 1. สิ่งที่ระบบทำได้

### โครงสร้างกลุ่มบริษัท
- บริษัทแม่–บริษัทลูกแบบไม่จำกัดชั้น (recursive)
- สลับบริษัทได้จากแถบบนสุด ข้อมูลแยกขาดจากกันด้วย Row Level Security
- ผู้ใช้ที่มีสิทธิ์ "มองเห็นบริษัทลูก" เห็นข้อมูลบริษัทในสายของตนแบบอ่านอย่างเดียว
- หน้า **ภาพรวมกลุ่มบริษัท** รวมรายได้ ค่าใช้จ่าย กำไร ลูกหนี้ เจ้าหนี้ เงินสด ของทุกบริษัทในหน้าเดียว

### เอกสารด้านรายรับ
ใบเสนอราคา · ใบวางบิล · ใบแจ้งหนี้ · ใบกำกับภาษี · ใบเสร็จรับเงิน · ใบลดหนี้ · ใบเพิ่มหนี้ · ใบรับเงินมัดจำ

### เอกสารด้านรายจ่าย
ใบขอซื้อ · ใบสั่งซื้อ · ใบรับสินค้า · ซื้อสินค้า/บริการ · บันทึกค่าใช้จ่าย · รับใบลดหนี้ · รับใบเพิ่มหนี้ · ใบจ่ายเงินมัดจำ

### บัญชีและรายงาน
- ผังบัญชีมาตรฐานไทย ~90 บัญชี (สร้างอัตโนมัติเมื่อเปิดบริษัทใหม่)
- ลงบัญชีอัตโนมัติเมื่ออนุมัติเอกสาร (Dr/Cr ครบ รวมภาษีซื้อ ภาษีขาย และภาษีหัก ณ ที่จ่าย)
- สมุดรายวัน · บัญชีแยกประเภท · งบทดลอง · งบกำไรขาดทุน · งบแสดงฐานะการเงิน
- รายงานอายุลูกหนี้ / อายุเจ้าหนี้ (5 ช่วงอายุ)

### ภาษี
- รายงานภาษีขายและภาษีซื้อรายเดือน (รูปแบบที่กรมสรรพากรกำหนด)
- แบบ ภ.พ.30 พร้อมคำนวณภาษีที่ต้องชำระ / เครดิตยกไป
- ตารางอัตราภาษีหัก ณ ที่จ่าย 18 ประเภทจริงตามประมวลรัษฎากร (ภ.ง.ด.1/2/3/53)

### ความปลอดภัย (ดูรายละเอียดในไฟล์ `SECURITY.md`)
- IP allowlist ที่ middleware · RLS ทุกตาราง · สิทธิ์ละเอียดระดับเมนู×การกระทำ
- ปิดงวด (Freeze) บังคับที่ระดับฐานข้อมูล · Audit trail ที่ลบไม่ได้ · Security headers

## 2. ติดตั้ง (ครั้งแรก)

### 2.1 สร้างโปรเจกต์ Supabase
1. ไปที่ https://supabase.com สร้างโปรเจกต์ใหม่ (แนะนำ region: Singapore)
2. เลือกรหัสผ่านฐานข้อมูลที่แข็งแรง และเก็บไว้ให้ปลอดภัย

### 2.2 รัน migration
เปิด **SQL Editor** ใน Supabase Studio แล้วรันไฟล์ในโฟลเดอร์ `supabase/migrations/` **ตามลำดับเลข**:

```
0001_extensions_and_schema.sql
0002_core_tables.sql
0003_accounting_tables.sql
0004_security_functions.sql
0005_triggers.sql
0006_rls_policies.sql
0007_seed_reference.sql
0008_provisioning.sql
0009_posting_engine.sql
0010_reports.sql
0011_bootstrap_admin.sql      <-- แก้อีเมลผู้ดูแลก่อนรัน
```

หรือใช้ Supabase CLI:
```bash
supabase link --project-ref <project-ref>
supabase db push
```

### 2.3 สร้างผู้ใช้ผู้ดูแลคนแรก
1. Supabase Studio → **Authentication → Users → Add user** (ใส่อีเมล + รหัสผ่าน, ติ๊ก Auto Confirm)
2. เปิดไฟล์ `0011_bootstrap_admin.sql` แก้ `v_admin_email` ให้ตรงกับอีเมลนั้น แล้วรัน
3. ระบบจะตั้งให้เป็น Group Admin และสร้างบริษัทแม่รหัส `HQ` พร้อมผังบัญชีและบทบาทมาตรฐาน

### 2.4 ตั้งค่าแอป
```bash
cp .env.example .env.local
```
กรอกค่าจาก Supabase Studio → **Project Settings → API**:

| ตัวแปร | ค่า |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon / public key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key (ห้ามเปิดเผย) |
| `ALLOWED_IPS` | IP/CIDR ของออฟฟิศหรือ VPN เช่น `203.0.113.0/24,10.0.0.0/8` |
| `APP_ORIGIN` | โดเมนที่ใช้จริง เช่น `https://accounting.internal.example.com` |

### 2.5 รัน
```bash
npm install
npm run dev        # http://localhost:3000
```

Production:
```bash
npm run build
npm run start
```

## 4. บทบาทมาตรฐาน (สร้างอัตโนมัติทุกบริษัท)

| บทบาท | สิทธิ์โดยสรุป |
|---|---|
| เจ้าของกิจการ | ทุกอย่างในบริษัทนั้น รวมปลดล็อกงวด |
| สมุห์บัญชี | บันทึก/อนุมัติ/ผ่านรายการ ปิดงวด ดู audit |
| พนักงานบัญชี | บันทึกและแก้ไข ไม่มีสิทธิ์ลบหรือปิดงวด |
| ฝ่ายขาย | เอกสารขาย + ลูกค้า **ไม่เห็นราคาทุนและงบการเงิน** |
| ฝ่ายจัดซื้อ | ใบขอซื้อ/ใบสั่งซื้อ + ผู้ขาย |
| ผู้บริหาร | อ่านอย่างเดียวทุกเมนู รวมงบการเงิน |
| ผู้ตรวจสอบ | อ่านอย่างเดียว + ดูประวัติการแก้ไข |

ปรับสิทธิ์เพิ่มเติมได้ที่ **ตั้งค่า → บทบาทและสิทธิ์** (ตารางติ๊ก 16 เมนู × 10 การกระทำ) บันทึกทันที

## 5. การนำขึ้นใช้งานจริงแบบปิด (แนะนำ)

1. รันบนเซิร์ฟเวอร์ภายใน (Docker / VM) — `next.config.mjs` ตั้ง `output: 'standalone'` แล้ว
2. วางหลัง reverse proxy (nginx) ที่เปิดเฉพาะวง LAN หรือ VPN (WireGuard / Tailscale)
3. ตั้ง `ALLOWED_IPS` ให้ตรงกับวงที่อนุญาต และเปิด `ENFORCE_IP_ALLOWLIST=true`
4. ใน Supabase: จำกัด Network Restrictions ให้รับเฉพาะ IP ของเซิร์ฟเวอร์แอป
5. เปิด MFA ให้ผู้ใช้ทุกคนใน Supabase Auth
6. ตั้ง Point-in-Time Recovery และสำรองฐานข้อมูลรายวัน

## 6. ข้อควรทราบ

- ตัวเลขภาษีที่ระบบคำนวณเป็นข้อมูลตั้งต้น **ควรให้ผู้ทำบัญชีสอบทานก่อนยื่นแบบกับกรมสรรพากรทุกครั้ง**
- ระบบยังไม่ตัดรายการระหว่างบริษัทในเครือ (intercompany elimination) — ตัวเลขในหน้าภาพรวมกลุ่มเป็นการรวมยอด
- ต้นทุนขายแบบ FIFO และโมดูลเงินเดือน/สินทรัพย์เป็นส่วนขยายที่ต่อยอดได้จากโครงสร้างเดิม
